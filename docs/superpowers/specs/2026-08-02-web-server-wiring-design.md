## 1. Цель и рамки

**Цель.** Довести проект до состояния «партия с друзьями в браузере»: веб-клиент перестаёт быть
витриной на скриптованном сценарии и работает против настоящего сервера — вход в комнату по HTTP,
поток состояния по WebSocket, реконнект, полный набор действий (включая голосование R-8.6),
доигрываемая до конца партия.

**Критерий-девиз.** Клиент остаётся **зрителем пушей** (W2-1) и **не считает правила** (W2-2):
любая интерактивность выводится из `snapshot.legal`, состояние меняется только приходящим
`update`. Итерация не добавляет игровой логики ни на одной стороне — она соединяет контракты.

**В рамках:**
- **B1. Синхронизация контракта.** TS-зеркала (W-3) дописываются до полного соответствия
  протоколу Слоя 2: 12 действий, 17 событий, `VoteView`, `stage`, `you`, `host`, `voteDeadline`.
  Закрывает §7.4 дизайна Слоя 2.
- **B2. Сеть на клиенте.** `contract/wire.ts` (кодек), `net/rooms.ts` (HTTP), `transport/ws.ts`
  (сокет + реконнект), `store/GameProvider.tsx` (стор на комнату вместо синглтона).
- **B3. Экраны.** Join создаёт/входит в комнату по HTTP; экран комнаты один, ветвится по `stage`;
  лобби умеет настройки партии и старт (у хоста); экран «место потеряно».
- **B4. Действия.** Все 12: недостающие `discardWest`, `declareOneCard`, `askCount`,
  `askAboutWest`, `claimSubjective`, `vote` получают UI-поверхности.
- **B5. Аддитивные правки Слоёв 1–2** — семь штук (§7), без которых сшивка неиграбельна или
  небезопасна: `host` в проекции, `error{seatNotFound}` перед закрытием сокета, переезд маршрутов
  на `/api` + `/ws`, кука `Path=/`, CORS, `OriginPatterns`, проба места `/me`.
- **B6. Golden-фикстуры протокола** — механизм, ловящий расхождение ручных зеркал автоматически.

**Вне рамок (следующие спеки / отложено):**
- **Общий тайм-аут хода / брошенная партия / фолд** (OQ-2/OQ-4) — в партии место держится
  бесконечно; ушедший навсегда игрок морозит стол. Не решается здесь.
- **Режим Culture** (D-10) — как и раньше, отложен.
- **Персистентное хранилище**, аккаунты/история, серия партий (R-10.2), Telegram-адаптер.
- **Кодогенерация типов из Go** — см. §3, подход отвергнут в пользу golden-фикстур.
- **Playwright/браузерный e2e** — приёмка вручную двумя вкладками (§10).

## 2. Ключевые решения (для этого спека)

Нумерация `W3-n`, чтобы не пересекаться с `W-n`/`W2-n` предыдущих итераций веб-клиента и `L2-n`
Слоя 2.

| # | Решение | Обоснование |
|---|---------|-------------|
| W3-1 | **Экран комнаты выбирается по `stage` из снапшота, а не по URL.** Маршрутов два: `/` (Join) и `/r/:code` (комната); что рисовать — лобби, стол или итог — решает `snapshot.stage`. `TABLE_ROUTE` удаляется. | Сервер авторитетен по стадии — пусть он ею и правит. Схема «стадия = URL» ломается ровно там, где это важнее всего: хост нажал «Начать» — у остальных URL не меняется; переподключился посреди партии — попал на лобби-адрес. |
| W3-2 | **API переезжает на `/api/rooms`, `/api/rooms/{code}/join`, `/ws/{code}`.** Адрес `/r/CODE` освобождается под страницу-инвайт. | D-2 дословно обещает инвайт-ссылку `/r/CODE`; сегодня там висит WS-эндпоинт, и страницу по этому адресу открыть нельзя. Разведение неймспейсов снимает коллизию навсегда. |
| W3-3 | **Ручное зеркало + golden-фикстуры протокола** вместо кодогенерации TS из Go. Go-тест выгружает реальные сообщения в `server/testdata/wire/*.json`, TS-тест их декодирует. | Генерировать не из чего: `protocol.go` кодирует не структуры, а собранные вручную `map[string]any`. Кодогенерация потребовала бы переписать закрытый кодек Слоя 2 на типизированные DTO. Фикстуры дают главное — расхождение падает красным в обоих репозиториях — за долю работы. Не мешают будущему переезду на DTO, а страхуют его. |
| W3-4 | **Раздельные origin + CORS** (фронт и сервер разъезжаются по адресам), кука `Path=/`, `SameSite=Lax` по умолчанию и `None; Secure` по флагу `-cross-site`. | Выбор владельца. В деве `localhost:5173` → `localhost:8080` — разные origin, но **один site**, поэтому `Lax` работает без TLS. Побочная польза: раздельные origin вынуждают задать WS `OriginPatterns`, чем закрывается `TODO(prod)` про `InsecureSkipVerify` (CSWSH). |
| W3-5 | **Действия при обрыве не буферизуются.** `send` в состоянии `reconnecting` отбрасывается с уведомлением; очереди нет. | За время обрыва позиция уходит вперёд; доставка отложенного действия — ход вслепую по чужому состоянию. Клиент — зритель пушей (W2-1), у него нет права на отложенное намерение. |
| W3-6 | **Модалка голосования открывается по `view.vote`, а не по событию `voteOpened`.** | Состояние переживает реконнект, событие — нет. Это прямой замысел `VoteView` (§8.3 Слоя 2): переподключившийся сразу видит идущий разбор. События используются только для показа исхода. |
| W3-7 | **Скриптованный транспорт и демо-сценарий удаляются** (`scripted.ts`, `mock.ts`, `fixtures/scenario.ts` с тестами). Тестам стора/экранов хватает инлайнового двойника `Transport` в несколько строк. | Двойник сервера был нужен, пока сервера не было. Держать его дальше — значит чинить демо-сценарий под каждое изменение снапшота ради витрины, которой пользуется только он сам. |

## 3. Отвергнутые подходы

**Кодогенерация TS-типов из Go** (tygo и аналоги). Отвергнута по W3-3: генерировать не из чего без
капитального рефакторинга закрытого `protocol.go`. Возможное будущее — отдельным спеком, если
ручной миррор разъедется ещё раз.

**Content-negotiation на `GET /r/{code}`** (есть `Upgrade` — вебсокет, нет — SPA). Отвергнута:
короткая ссылка без переезда API, но один эндпоинт с двумя несвязанными смыслами — хрупко и
непрозрачно в логах/метриках.

**Оставить сервер как есть, инвайт-ссылка `/room/CODE`.** Отвергнута владельцем в пользу W3-2:
ссылка, которую шарят в чате, должна быть короткой, а D-2 хочется сохранить дословно.

## 4. Архитектура клиента

Слои внутри `web/src/` (★ — новое):

```
contract/types.ts        зеркала движка (W-3), дополненные до полноты протокола.
contract/wire.ts      ★  ЕДИНСТВЕННОЕ место, знающее JSON-формат сервера:
                         decodeServerMsg / encodeAction. Всё остальное работает
                         с типами, а не с сырым JSON.
net/rooms.ts          ★  HTTP: createRoom(name, cfg) → {code};
                         joinRoom(code, name) → {seat}; me(code) → проба места
                         (§7.7). Всегда credentials:'include'.
transport/ws.ts       ★  сокет + авто-реконнект с бэкоффом + reqId/ack/error +
                         поток ConnState. Реализует существующий Transport.
store/game.ts            createGameStore(transport) — есть; синглтон снимается,
                         добавляются connState и lastError.
store/GameProvider.tsx ★ React-контекст: создаёт стор на код комнаты, рвёт при уходе.
ui/screens/Room.tsx   ★  один экран комнаты, ветвится по stage (W3-1).
ui/screens/Lost.tsx   ★  «место потеряно» + возврат на Join.
```

Шов `Transport` (`subscribe`/`send`) из итерации 1 **не меняется** — он ровно для этого и
закладывался. `ws.ts` расширяет его наблюдаемым состоянием соединения (§9).

**Поток данных:**

```
Join («/»): имя + «Создать»  → POST /api/rooms → {code}, кука в ответе
                              ↓ navigate(`/r/${code}`)
Room («/r/:code»): GET /api/rooms/{code}/me   ← проба места (§7.7)
  ├─ 200 {seat}          → место есть, подключаемся
  ├─ 401 seatNotFound    → форма «Ваше имя» → POST /api/rooms/{code}/join → подключаемся
  └─ 404 roomNotFound    → экран «Комната не найдена»
                              ↓
GameProvider: createGameStore(createWsTransport(code))
                              ↓ GET /ws/{code}  (кука уходит автоматически)
   сервер → update{you,roomCode,stage,host,roster,view,legal,events,voteDeadline}
                              ↓ decodeServerMsg
   store.snapshot → Room.tsx по stage → Lobby | Table | Finish
```

**Вход по инвайт-ссылке — основной сценарий шаринга, и он проходит через ту же пробу.** Друг
открывает `/r/CODE` без куки, получает 401 и форму имени прямо на этом экране — без прыжка на
Join и без повторного ввода кода. Поэтому экран Join сводится к «имя + Создать комнату»: поле
кода на нём — просто навигация на `/r/CODE`, вся логика присоединения живёт в одном месте.

Имя игрока хранится в `localStorage` (`shukh.name`) и подставляется в форму — переприсоединение
после истёкшего grace в одно нажатие.

Стадия `finished` рисует стол с итоговым порядком (`view.finish`, R-10.1) и кнопкой выхода на
Join; новая партия в этой итерации не запускается (серия партий R-10.2 — «позже» по дорожной
карте).

Отправка односторонняя (W2-1): `send` шлёт `action` с `reqId` и **не трогает состояние**;
рендерится только пришедшее в `update`. `ack` гасит индикацию отправки, `error` поднимает
уведомление.

## 5. Мэппинг протокола

`ServerMsg{type:"update"}` → `GameSnapshot`:

| сервер | клиент | комментарий |
|---|---|---|
| `you` | `you: SeatID` | новое поле снапшота: в лобби `view === null`, а своё место знать надо |
| `roomCode` | `roomCode` | — |
| `stage` | `stage: 'lobby'\|'playing'\|'finished'` | новое; правит экраном (W3-1) |
| `host` | `host: SeatID` | новое, аддитивная правка Слоя 1 (§7.1) |
| `roster[]` | `seats[]` | `{seat, name}`; **`ready` удаляется** — Слой 1 такого понятия не имеет |
| `view` | `view: SeatView \| null` | + новое `view.vote?: VoteView` |
| `legal[]` | `legal[]` | без изменений |
| `events[]` | кольцевой буфер стора | `EVENTS_CAP` как есть |
| `voteDeadline` | `voteDeadline?: number` | unix-мс, для обратного отсчёта |

`ServerMsg{type:"ack"|"error"}` не трогают снапшот: `ack{reqId}` снимает индикацию отправки,
`error{reqId,code,message}` кладётся в `lastError` стора.

**Чего не хватает в TS-зеркалах** (накопленный разрыв, §7.4 Слоя 2):

- **`Action` — добавить 6:** `discardWest`, `declareOneCard`, `askCount`, `askAboutWest`,
  `claimSubjective`, `vote`. Итого 12.
- **`GameEvent` — добавить 4:** `oneCardDeclared`, `westDiscarded`, `voteOpened`, `voteResolved`.
  Последние два несут ритуал голосования — без них исход разбора не показать.
- **`ShukhCode`** — сейчас `2|3|11|12`; добавляются субъективные `6|9|10` и `8` (исход
  оспаривания, R-8.6).
- **`SeatView.vote?: VoteView`** — `{claimant, target, code, voted[]}`.
- **Удаляется `ShukhVote`** — выдуманный в 2c DTO с голосами и исходом; сервер такого не шлёт и не
  может (тайна бюллетеня §8.4 Слоя 2).

**Самозащита кодека.** `decodeServerMsg` — узкие type guards, а не приведение типов. Неизвестный
`type` события или действия — не молчаливый пропуск, а явная ошибка: единственное, что нас
по-настоящему больно кусает, — расхождение зеркал, и оно должно быть громким.

## 6. Действия и UI-поверхности

**ActionBar — свои действия, все гейтятся `legal`:** «Сходить» (подтверждение выбранной карты),
«Взять низ», «Западло», «Сбросить Запад» (эндшпиль §9.2 — без него партия на двоих встаёт),
«ШУХ!» (объективный: сервер сам кладёт в `legal` конкретную цель и код), «Одна карта!»,
«Взять ШУХ». Оплата ШУХа (`giveShukhCard`) — выбор карты из руки при открытом гейте §8, как в 2c.

Отдельно: **«Одна карта!» сегодня ничего не отправляет** — в 2c это клиент-локальное объявление.
Теперь это настоящее `declareOneCard`, и Ш-11 начинает ловиться по правилам.

**Меню на месте соперника** — клик по `OpponentSeat`:
- «Сколько карт?» (`askCount`, R-6) и «Есть Запад?» (`askAboutWest`, R-9.4.2) — пункты видны,
  только когда есть в `legal`;
- «ШУХ: завис (Ш-6) / зря крикнул (Ш-9) / небрежность (Ш-10)» — `claimSubjective` доступен всегда
  в стадии `playing`, потому что движок сознательно **не перечисляет** его в `legal` (это
  «всегда доступная социальная кнопка, валидируемая на сабмите»); отказ приходит ошибкой сервера.
- Клавиатура и Esc — как у прочих интерактивных элементов 2c; `aria-disabled` только на
  интерактивных узлах.

**Модалка голосования** — на реальных данных:
- открывается по `view.vote != null` (W3-6);
- показывает «кто кого и за что» (`claimant`/`target`/`code`), список **отдавших** голос без
  содержания (тайна бюллетеня §8.4 Слоя 2) и обратный отсчёт из `voteDeadline`;
- кнопки «За ШУХ» / «Против ШУХа» берутся из `legal` — проголосовавший получает пустой `legal`,
  кнопки гаснут сами (движок замораживает стол на время разбора, §15.8);
- исход — из события `voteResolved{code, overturned}`;
- дедлайн истёк, апдейта ещё нет → «подводим итог…»: сервер закроет разбор сам через `CloseVote`.

## 7. Аддитивные правки Слоёв 1–2

Слои влиты и закрыты; правим **аддитивно**, каждая правка — с тестом на Go-стороне.

### 7.1 `host` в проекции (Слой 1 + 2)
`game.Update` получает поле `Host engine.SeatID`, `encodeUpdate` — `"host"`. Без него клиент не
знает, он ли хост, то есть показывать ли «Начать» и настройки партии. Альтернатива без правки —
показывать кнопку всем и ловить `error{notHost}` — плоха сама по себе и вовсе не работает при
миграции хоста (L2-3): новый хост не узнает, что стал хостом.

### 7.2 `error{seatNotFound}` перед закрытием сокета (Слой 2)
Если `Subscribe` отказал (место освобождено после grace в лобби), `serveConn` сейчас закрывает
сокет молча — клиенту нечего показать, и авто-реконнект будет биться в стену. Отправляем
`error{code:"seatNotFound"}` перед закрытием.

### 7.3 Переезд маршрутов (Слой 2)
`POST /api/rooms`, `POST /api/rooms/{code}/join`, `GET /ws/{code}`. Адрес `/r/CODE` больше не
занят сервером и остаётся страницей-инвайтом (W3-2, D-2).

### 7.4 Кука (Слой 2)
`Path=/` — должна уходить и на `/api/...`, и на `/ws/...`. Имя остаётся пер-комнатным
(`shukh_<code>`), так что несколько комнат в одном браузере по-прежнему сосуществуют.
`SameSite=Lax` по умолчанию; флаг `-cross-site` переключает на `None; Secure` для развёртывания на
разных сайтах.

### 7.5 CORS (Слой 2)
Middleware с allowlist из флага `-origins`: `Access-Control-Allow-Origin` (эхо разрешённого
origin, не `*` — с credentials звёздочка запрещена), `Access-Control-Allow-Credentials: true`,
обработка preflight `OPTIONS` (POST с `Content-Type: application/json` его провоцирует).

### 7.6 `OriginPatterns` для WS (Слой 2)
`InsecureSkipVerify` заменяется на `OriginPatterns` из того же allowlist — закрывается
`TODO(prod)` про CSWSH.

### 7.7 Проба места `GET /api/rooms/{code}/me` (Слой 2)
Возвращает `200 {seat}` при живом месте, `401 {error:"seatNotFound"}` без куки/с неизвестным
токеном, `404 {error:"roomNotFound"}` для несуществующей комнаты.

Нужна потому, что **браузерный `WebSocket` API не показывает статус неудавшегося рукопожатия** —
только «не открылось». Сервер же отвергает вход именно до апгрейда (401/404 в `connect`), так что
без пробы клиент не отличит «нет места» от «сервер лежит» и будет вечно долбиться бэкоффом в
стену. Проба выполняется перед первым подключением (она же ведёт вход по инвайт-ссылке, §4) и
повторно — когда сокет не открылся.

Отдельно от неё остаётся случай §7.2: место освободилось **после** успешного апгрейда — там
причина приходит уже сообщением по сокету.

`cmd/shukh-server` получает флаги `-addr`, `-origins`, `-cross-site`.

## 8. Жизненный цикл соединения

`ConnState`: `connecting | open | reconnecting | lost`.

```
    connecting ──open──► open ──close/error──► reconnecting ──┐
        │                                          ▲          │
        │                                          └──────────┘ бэкофф 0.5s→8s, ×2, бесконечно
        └── error{seatNotFound} по сокету (§7.2) ─────────► lost
        └── сокет не открылся → проба /me (§7.7):
              401 seatNotFound / 404 roomNotFound ────────► lost
              иначе (сеть/сервер) ────────────────────────► reconnecting
```

- Бэкофф — экспоненциальный с потолком 8 c и небольшим джиттером, попытки не ограничены (мобильный
  браузер рвёт сокет при каждом уходе в фон — ручное переподключение там мучительно).
- В `reconnecting` стол виден по последнему снапшоту, действия заблокированы, сверху баннер.
  Отправка отбрасывается (W3-5).
- `lost` — терминальное: экран «место потеряно» с кнопкой возврата на Join (код и имя
  подставлены).
- Реконнект бесшовен на стороне сервера: grace 5 минут (§5.4 Слоя 2), close-and-replace в
  `Subscribe` (§6.4 Слоя 2), первый же `update` после переподключения — полный снапшот.

## 9. Обработка ошибок

| Источник | Что показываем |
|---|---|
| `GET /api/rooms/{code}/me` → 404 | экран «Комната не найдена» с возвратом на Join |
| `GET /api/rooms/{code}/me` → 401 | форму «Ваше имя» на экране комнаты (вход по ссылке, §4) |
| `POST /api/rooms/{code}/join` → 409 (`full`/`duplicate`) | «Комната заполнена» / «Имя занято» под формой |
| WS `error{illegalAction}` | уведомление; состояние не трогаем (движок его не менял) |
| WS `error{notYours\|notPlaying\|notHost\|notLobby\|tooFewPlayers}` | уведомление текстом по коду |
| WS `error{seatNotFound}` | терминальный `lost` (§8) |
| сокет не открылся | проба `/me` решает: `lost` или `reconnecting` (§8) |
| обрыв установленного сокета | баннер `reconnecting` |

Оптимистичных обновлений нет ни в одном случае: расхождение с сервером невозможно по построению.

## 10. Тестирование

**Golden-фикстуры протокола (W3-3) — ядро защиты от рассинхрона:**
- **Go `TestProtocolGolden`** прогоняет типовые позиции — лобби, старт партии, ШУХ-окно Middle,

  или изменение формы на стороне Go роняет тест на стороне TS. Это и есть замена кодогенерации.

**Юниты клиента:**
- `ws.test.ts` на фейковом `WebSocket`: update → снапшот, `ack` по `reqId`, `error` → `lastError`,
  обрыв → бэкофф-реконнект (фейковые таймеры), `seatNotFound` → `lost`, отписка закрывает сокет.
- `rooms.test.ts` на двойнике `fetch`: `credentials: 'include'`, 404/409 → типизированные ошибки.
- Экранные тесты — на инлайновом двойнике `Transport` (несколько строк в самом тесте, отдельного
  файла-двойника больше нет, W3-7).

**Go-сторона:** тесты новых маршрутов, CORS-заголовков и preflight, куки (`Path`, `SameSite` в
обоих режимах), `error{seatNotFound}` перед закрытием, `host` в апдейте, три исхода пробы `/me`

**Гейт (из `web/`), обязателен в конце каждой задачи плана:**
`npm run typecheck && npm run lint && npm test` — всё зелёное. Со стороны Go: `go build ./... &&
go test ./...`.

## 12. Известные ограничения (в MVP не решаем)

- **Ушедший навсегда игрок морозит стол** в стадии `playing`: grace защищает только от обрывов,
  общего тайм-аута хода нет (OQ-2/OQ-4).
- **Комнаты эфемерны** — состояние in-memory; рестарт сервера теряет партии (шов `RoomStore`
  заложен, реализации нет).
- **Смена имени и выбор места** не поддерживаются: имя фиксируется при входе, место — порядком
  входа (R-4.7).
- **Режим Culture** выбирается в настройках комнаты, но движок его не реализует (D-10).

## 13. Как это стыкуется с дорожной картой

Закрывает §7.4 дизайна Слоя 2 (расхождения контракта) и делает Спец 3 играбельным. После этой
итерации дорожная карта упирается в OQ-2/OQ-4 (тайм-аут хода) — первый кандидат на следующий спек,
поскольку без него сетевая партия рвётся на первом же ушедшем игроке.
